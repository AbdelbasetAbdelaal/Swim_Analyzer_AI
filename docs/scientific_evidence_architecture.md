# Scientific Evidence Architecture

## Overview
The Scientific Evidence Architecture transforms SwimAnalyzer AI from a heuristic-based system to a scientifically rigorous platform. It enforces a strict evidence-first approach, ensuring that every benchmark value presented to users is derived from peer-reviewed scientific literature.

## Core Entities
The system strictly distinguishes between different stages of scientific data lifecycle:

1. **Domain References (Sources)**
   *   Represent actual scientific papers or publications.
   *   Tracked in `ScientificSourceRegistry` (backed by `source_registry.yaml`).
   *   Require verified PMIDs or DOIs.

2. **Candidate Evidence**
   *   Raw data extracted from papers (often by Gemini or other LLMs).
   *   Treated as UNTRUSTED and requires strict deterministic validation.

3. **Validated Evidence (Evidence Records)**
   *   Specific metric cohorts extracted from a Domain Reference.
   *   Must pass strict validation rules (no metric mismatch, correct population constraints, valid units).
   *   Tracked in `ScientificEvidenceRegistry` (backed by `evidence_registry.yaml`).

4. **Aggregated Evidence**
   *   The result of combining multiple Validated Evidence records for the same demographic and stroke.
   *   Averages means and standard deviations, weighted by sample size.
   *   Handled by `EvidenceAggregator`.

5. **Benchmarks**
   *   The final output served to the UI/Engine.
   *   Generated by `ScientificBenchmarkBuilder`.
   *   Every benchmark *must* contain a full provenance trace (source IDs, evidence IDs, validation status) pointing back to the Aggregated Evidence.

## Data Flow
`Scientific Updater Pipeline` -> `Literature Discovery` -> `Candidate Extraction` -> `Evidence Validator` -> `Evidence Registry` -> `Evidence Aggregator` -> `Benchmark Builder` -> `Benchmark Engine` -> `Streamlit UI / PDF Reports`

## Key Principles
*   **No Synthetic Scores:** Fabricated scores or heuristic guesses are rejected. If evidence is missing, the system explicitly reports `INSUFFICIENT_EVIDENCE`.
*   **Untrusted AI Extraction:** Gemini is strictly limited to extracting *candidates*. It cannot approve, assign, or create benchmarks directly. All AI outputs must pass deterministic Python validation.
*   **Strict Demographics:** Benchmark values are restricted to exactly the populations described in the underlying literature. Adult male statistics are not silently mapped to female or youth athletes.
